# Component measurement contract

Every public runtime export must have exactly one fixture. A missing or extra fixture fails the runner. Fixtures use only synthetic data, native controls, and deterministic changed props. The Table fixture includes 100 rows and three columns; CodeBlock includes 40 records. Every fixture is audited independently.

`npm run bench` builds two bundles: ordinary production React for first paint/FCP and Lighthouse, and production profiling React for controlled rerender durations. Three cold browser contexts supply median paint measurements; no network or CPU throttling is applied. Viewport is 1280×900 with reduced motion. Five warmups are excluded, then 30 updates record React subtree render duration and latency through two animation frames. The latter includes frame scheduling and is not JavaScript execution time.

Budgets live in `budgets.json`. Paint/FCP are fixture navigation metrics including framework/bootstrap, shared CSS and fixture headings. React profiling has overhead and timer precision limits; compare like environments rather than interpreting fractions of a millisecond as universal values. Reports retain every raw sample, environment metadata and per-component Lighthouse JSON. Accessibility scores are automated fixture coverage and are not manual WCAG certification.

The workflow runs on every push to main and pull request. Absolute budgets fail immediately. On pull requests, both the base revision and head are built and benchmarked sequentially on the same runner; comparisons enforce a 30% regression limit plus a versioned noise allowance. Different CPU/platform/architecture/Node/viewport/throttling environments are rejected. A first commit has no prior harness, so absolute budgets apply until a comparable base exists. A disappeared fixture or reduced accessibility score fails. New fixtures are reported separately and must meet absolute budgets.

Reports and audit details are uploaded as workflow artifacts for 90 days and the component table appears in the workflow summary. Download and preserve artifacts for longer historical retention; GitHub artifact retention is not permanent storage. Manual workflow dispatch supports measurement outside a PR. Release publishing uses npm provenance with an owner-configured npm trusted publisher; this configuration is not established merely by checking in the workflow.
